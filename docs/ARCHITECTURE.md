# 代码理解指南

这份项目最值得理解的不是每一行语法，而是下面四层关系。

## 1. 模型客户端

`mini_agent/model_client.py` 只负责向 OpenAI 兼容接口发送消息和工具定义。它不执行文件操作，也不决定循环何时结束。

这样设计的原因是将“访问模型”和“Agent 如何工作”分开。更换模型服务时，通常只需要修改这一层。

## 2. 本地工具

`mini_agent/tools.py` 有两部分：

- `TOOL_DEFINITIONS`：告诉模型有哪些工具、每个工具需要什么参数。
- `WorkspaceTools`：真正读取文件、写入文件和执行命令。

模型生成工具调用只是在提出请求，`WorkspaceTools.execute()` 才真正操作电脑。

`_resolve()` 拒绝绝对路径和工作区外路径。`edit_file()` 仅在旧文本恰好出现一次时进行精确替换，避免为了改一行而覆盖整个文件。

`run_command()` 设置超时、截断过长输出，并拦截部分明显危险命令。它返回结构化的 `exit_code`、`stdout` 和 `stderr`；退出码非零时，工具结果的 `ok` 为 `false`，模型仍然可以读取失败输出并继续修复。

## 3. Agent 主循环

`mini_agent/agent.py` 中的 `CodingAgent.run()` 是核心：

```text
发送任务和工具定义
        ↓
读取模型回复
        ↓
有工具调用？ ── 否 ──→ 返回最终文本
    │
    是
    ↓
本地执行工具
    ↓
把结果加入 messages
    ↓
进入下一轮
```

最大轮数是独立终止条件。即使模型一直调用工具，程序也不会无限运行。

## 4. 命令行入口

`mini_agent/cli.py` 负责读取环境变量、选择工作区、组装模型和工具，然后显示运行过程。它属于用户界面，不包含 Agent 的核心决策逻辑。

## 5. 安全边界

文件工具会解析真实路径并拒绝逃出工作区。命令工具设置工作目录、超时和输出限制，也拦截部分明显危险的命令。

但命令黑名单不等于操作系统沙箱：子进程理论上仍可能访问本机其他路径。生产环境应把工具放入容器、虚拟机或受限账户中运行。本项目选择保持实现小而清楚，演示时只使用独立且可恢复的工作区。

## 面试时最简短的介绍

这个项目没有使用 Agent 框架。模型负责决定下一步调用哪个工具；我编写的程序负责校验参数、在本地执行工具、把结构化结果返回模型，并循环到模型给出最终答案。文件访问被限制在指定工作区内，命令有退出码、超时和输出限制，循环也有最大轮数。
